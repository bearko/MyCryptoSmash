# bearko.games の共通基盤とのつなぎ

My Crypto Smash は、bearko.games の共通基盤（共通ログイン・アチーブメント・総合スコア・RTA・全体チャット・分析）に参加する。
共通基盤の側の手順は bearko/MyCryptoPortfolio の `docs/INTEGRATION.md`（3 章）と `sdk/v1.js` の先頭のコメント。

- タイトル ID：`smash`　ホスト：`smash.bearko.games`
- 窓口：`src/ui/platform.ts`。ほかのファイルは `window.BearkoGames` を触らず、ここの関数だけを呼ぶ
- SDK：`index.html` の `<head>` で `https://bearko.games/sdk/v1.js` を読む（defer。ゲーム本体の module より前）
- 起動：`main.ts` が `startPlatform()` を 1 回呼ぶ。SDK がまだ無ければ `load` のときにもう一度見る

## 守ること

- **SDK が読めない・通信に失敗しても、最後まで遊べる**。窓口の呼び出しは全部 try/catch で包み、失敗は `console.warn` だけ（`tests/platform.test.ts` が確かめる）
- ゲームは Cookie を触らない。ログイン状態は共通基盤が持つ
- 外部の解析タグや自前のプレイログは入れない。数は共通基盤の管理画面で見る
- `init({ presence: false })` にしない（来訪が止まり、KPI が出なくなる）

## 共通基盤の側に要る登録（まだ）

2026-11-27 の時点で、`smash` は共通基盤に登録されていない。ゲーム側は登録されていなくても動く（呼び出しが失敗しても warn だけ）。共通基盤の側（bearko/MyCryptoPortfolio）で要ること：

- `platform/trophies.js` の `GAME_HOSTS` に `smash: 'smash.bearko.games'` を足す（CORS・チュートリアルの段・チャットの札の受け付けに要る）
- 同じファイルの表示名の表（`football: 'MyCryptoFootball'` の並び）に `smash: 'MyCryptoSmash'`、来訪のアチーブメント `smash.visit`（`visit: true`。名前・アバターは MCH のスキル名から）を足す。**これが無いと `/api/trophies/visit` が 400（`{"error":"game"}`）になり、KPI の「遊んだ日」が数えられない**（2026-11-27 にローカルの共通基盤で確かめた）
- `sdk/v1.js` の `GAME_LABEL` に `smash: 'Smash'`（チャットの札の表示）
- `docs/INTEGRATION.md` の 1 章の表と、3.1 のタイトル ID の一覧に Smash を足す
- 管理画面の「チュートリアル」タブ用に、下の段の表を伝える
- アチーブメント・総合スコア・RTA は、下の案が決まってから

## init の中身

```js
BearkoGames.init({ game: 'smash', version, chat: { layout: 'float', button: false }, toast: 'top', toastOffset: 64 })
```

- `version` は `package.json` の版

## 全体チャット

- `chat: { layout: 'float', button: false }`：**PC の右側のドックも、右下の 💬 も出さない**。ホーム画面の「チャット」と、設定のシートの「チャット」から窓を開く（`openChat()`。どちらも SDK が読めたときだけ出る。`platformOn()`）
- 理由：台が画面いっぱい（PC は 3 列）で、右のドックはラボの列を、右下の 💬 は打ち出しの通路を隠す
- **プレイ中は隠す**：打ち出してから RESULT までの間 `chat.setVisible(false)`、遊んでいないときに `setVisible(true)`（`setPlaying()`。`main.ts` の毎コマの見回りから、変わったときだけ呼ぶ）。ホーム画面に戻っている間は、プレイの途中でも出す
- 時間は止めない（40 秒のプレイ中は窓を開けない）
- 知らせ（アチーブメントなど）は画面の上、上の帯（GUM・時間・設定。約 60px）の下に出す（`toast: 'top'`・`toastOffset: 64`）。下は打ち出しの手元とフッター
- **導入・口上・エンディング**（`#app > .story`。暗い画面で見せる場面）の間も隠す

## チュートリアルの段

はじめての人がどこで離れるかを、管理画面の「チュートリアル」タブで見るためのもの（`tutorialStep(step, id)`）。
チュートリアルは、**はじめての挑戦のノルマ 0 の案内**（`docs/GAME_DESIGN.md` の「チュートリアル」。導入で名前を決めたところから、本当のノルマ 1 の 1 プレイ目を打ち出すまで）。

| 番号 | id | いつ送るか |
|---|---|---|
| 0 | `start` | 案内つきのチュートリアルが始まった（導入で名前を決め、ノルマ 0 の台に来た） |
| 10 | `launch_1` | ノルマ 0 の 1 プレイ目を打ち出した |
| 20 | `buy_sling` | ③三角のばねを買った |
| 30 | `launch_2` | 2 プレイ目を打ち出した |
| 40 | `buy_inlane` | ④内側の通路を買った |
| 50 | `launch_3` | 3 プレイ目を打ち出した |
| 60 | `deposit` | 入金口にノルマ 0 を納めた（ノルマ 1 になった） |
| 70 | `buy_bumper` | ⑦丸いばねを買った（ふつうは納めたごほうびのエンブレムで） |
| 90 | `done` | チュートリアルが終わった：本当のノルマ 1 の 1 プレイ目を打ち出した。または「案内をとばす」を押した |

- **番号と id は、公開したあとに変えない**（変えると前後の数を比べられなくなる）。足すときは空いている番号に入れる
- セーブされている内容から段を判定する（`tutorialSteps(save)`。`writeSave` のたびに、書く直前に `trackTutorial` が呼ばれる：`save.ts` の `onCommit`）
- 送るのは、案内つきのチュートリアルを始めたセーブだけ：ノルマ 0・`quota.guide`・`tutorialDone` でない・名前があるセーブを見たときに `save.tutTrack` の印を付け、印のあるセーブのノルマ 0〜1 だけを見る。前からのセーブ・2 回目からの挑戦・ノルマ 2 から先・ラストステージ・エンドレスでは送らない
- `done` は `tutorialState(save).guided` が false になったとき（本当のノルマ 1 を打ち出した・案内をとばした）。とばしたあとも遊びつづければ、着いた段（ノルマ 0 の打ち出し・部品を買った・納めた）は送る
- 同じ段は 1 回だけ送る（窓口・SDK・サーバーのどれもが最初の 1 回だけ残す）。SDK が読める前に着いた段は、読めたときにまとめて送る
- 「はじめから」でセーブを消すと、次の導入からまた数える（サーバーは人ごとに最初の 1 回だけ残す）

## アチーブメント・総合スコア・RTA（案）

共通基盤の側に定義が足されるまでは、呼び出しの口だけがある（`unlockTrophy`・`submitScore`・`rta`）。ゲームからはまだ呼んでいない。
下は案。決まったら「案」を外して、ここを正にする。

### アチーブメント（条件の案。名前と絵は共通基盤の側で決める）

| 仮の名前 | 条件 | 種類 |
|---|---|---|
| `tutorial` | チュートリアルのノルマ 0 を納める | 軽い目標 |
| `quota3` | ノルマ 3 を納める | 最初の節目 |
| `joker` | 台に宿るピエロをジョーカーにする | 節目 |
| `normal_end` | ノルマ 10 を納める（通常のエンディング） | 節目 |
| `escape` | ラストステージを突破して脱出する（真のエンディング） | ゲームクリア |
| `endless10` | エンドレスでノルマ 10 を納める | めずらしい |
| `legendary` | エクステンションをレジェンダリーまで重ねる | 軽い目標 |

来訪（`smash.visit`）は SDK が送るので、ゲームでは作らない。

### 総合スコア（案）

- 種類：`progress`（スキルツリーは GAME OVER でも残るので、積み上げ）
- 送るもの：`{ best, escapes, clears, endlessBest, plays }`（いちばん先まで納めたノルマ・脱出の回数・通常のエンディングの回数・エンドレスの記録・打ち出したプレイの数）
- 送る時機：ノルマを納めたとき（`{ quiet: true }`）と、エンディングのあと（通知あり）

### RTA（案）

- レギュレーション `smash-escape`（導入から脱出まで）：区切り `quota1` → `quota5` → `quota10` → `escape`。ゲーム内の時間はプレイの数（`igt: 'plays'`）
- ホーム画面に「RTA で始める」の入口が要る（まだ無い）
